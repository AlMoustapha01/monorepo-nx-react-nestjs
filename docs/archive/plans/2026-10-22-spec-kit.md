# Spec Kit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un projet cloné depuis le boilerplate développe ses fonctionnalités avec Spec Kit (Claude Code prêt dès le clone), avec une constitution, des templates et des commandes qui imposent l'architecture du boilerplate et le TDD.

**Architecture:** Spec Kit 1.2.2 est initialisé à la racine et commité (`.specify/`, `.claude/skills/speckit-*`). Toutes les personnalisations vivent dans un **preset local** dont la source est versionnée dans `tools/spec-kit/preset/` et installée par `specify preset add --dev` (copie dans `.specify/presets/boilerplate/`, commitée). Templates : stratégie `replace`. Commandes `implement` et `converge` : stratégie `append`, pour garder le cœur de Spec Kit à jour. La constitution est écrite à la main. La doc vit dans `AGENTS.md`.

**Tech Stack:** Spec Kit (`specify-cli` 1.2.2, via `uvx`), scripts bash de Spec Kit, Markdown, oxfmt.

**Spec:** `docs/superpowers/specs/2026-10-22-spec-kit-design.md`

## Global Constraints

- Version épinglée partout : `specify-cli==1.2.2` (`uvx --from specify-cli==1.2.2 specify …`). Le preset déclare `speckit_version: ">=1.2.2"`.
- Intégration : `claude`, scripts `sh`. Aucune autre intégration commitée.
- Specs, plans, tâches, constitution, templates et commandes du preset : **en anglais**. `AGENTS.md` et le README : en français, comme aujourd'hui.
- La constitution renvoie à `AGENTS.md`, qui fait foi ; elle ne recopie pas les règles une à une.
- Aucune modification de `.github/workflows/`.
- Pas de feature flag (outillage). Moins de 500 lignes **hors fichiers générés** (`.specify/` hors constitution, `.claude/skills/`) ; sinon deux PR : tâches 1–3, puis 4–5.
- `pnpm check` passe à la fin de chaque tâche.
- Commits conventionnels en anglais, terminés par les lignes d'attribution de la session. Working tree partagé avec une session front : `git add` uniquement des chemins listés dans la tâche, jamais `git add -A` ni `git stash`.

## Review Focus

1. **Mise à jour de Spec Kit** (`specify init --here --force` d'une version plus récente) : les commandes `implement`/`converge` doivent garder la section TDD. Tâche 5 documente la réinstallation du preset (`specify preset update boilerplate --dev tools/spec-kit/preset`) et la vérification ; Tâche 3 vérifie qu'un `preset update` regénère bien les skills.
2. **Autre agent** (`specify integration install copilot` puis `use copilot`) : le preset doit être réappliqué aux fichiers de cet agent. Tâche 3 le vérifie dans un clone jetable.
3. **Source et copie installée du preset divergent** (quelqu'un édite `.specify/presets/boilerplate/` au lieu de `tools/spec-kit/preset/`) : Tâche 5 documente que la source fait foi ; Tâche 3 ajoute un en-tête de commentaire dans chaque fichier source qui le rappelle.
4. **`pnpm format:check` sur les fichiers générés ou les specs écrites par l'agent** : oxfmt reformate le Markdown, le JSON et le YAML générés (constaté). Tâche 1 exclut `.specify/`, `.claude/skills/speckit-*/` et `specs/` ; Tâche 4 vérifie qu'une spec créée ne casse pas `format:check`.
5. **État local commité par erreur** (`.specify/feature.json`, pointeur de la feature active) : le `.gitignore` de `.specify/` l'exclut déjà ; Tâche 4 vérifie qu'après `create-new-feature.sh` le fichier n'apparaît pas dans `git status`.

- [ ] **Step 3 : `plan-template.md`**

- [ ] **Step 4 : `tasks-template.md`**

À partir de `.specify/templates/tasks-template.md` :

- Les tests ne sont plus optionnels : supprimer toutes les mentions « OPTIONAL » / « if tests requested ».
- Par user story, l'ordre est : tests (un par scénario d'acceptation, chemin réel : `*.spec.ts` à côté du code, `*.int.spec.ts`, `apps/api/tests/<domain>.e2e.spec.ts`, `apps/web-e2e/src/*.spec.ts`) avec la mention « run it and confirm it FAILS for the expected reason », puis implémentation minimale, puis refactor.
- Phase « Foundational » : feature flag déclaré dans `FEATURE_FLAGS`, contrats zod, schéma Drizzle + migration (`pnpm nx run api:db-generate --name=<topic>`).
- Chemins d'exemple et commandes de vérification adaptés au repo (`pnpm nx test <project>`, `pnpm nx affected -t lint typecheck test`).
- Règle : une user story tient dans une PR de moins de 500 lignes ; sinon la découper en plusieurs stories.

- [ ] **Step 5 : `commands/speckit.implement.md` (ajouté à la fin de la commande)**

Section `## Test-First Rules (boilerplate)` :

- Ne jamais écrire de code de production avant le test qui l'exige.
- Une tâche de test n'est cochée qu'après avoir lancé le test et constaté qu'il échoue pour la raison attendue (citer la sortie).
- Une tâche d'implémentation n'est cochée qu'après le passage de ses tests et de `pnpm nx affected -t lint typecheck test`.
- Si un test passe dès sa première exécution, s'arrêter et le signaler : soit le comportement existe déjà, soit le test ne teste rien.
- Ces règles priment sur toute instruction plus haut qui les contredirait.

- [ ] **Step 6 : `commands/speckit.converge.md` (ajouté à la fin de la commande)**

Section `## Test Coverage of Acceptance Scenarios (boilerplate)` : pour chaque scénario d'acceptation de `spec.md`, chercher le test qui le couvre ; s'il n'y en a pas, c'est un écart, et ajouter une tâche de test (avant toute tâche d'implémentation liée), au format du template. Ne pas conclure **Converged** tant qu'un scénario n'a pas de test.
